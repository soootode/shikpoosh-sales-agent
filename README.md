# 🛍️ شایان | دستیار فروش هوشمند فروشگاه شیک‌پوش

> 🔗 **دموی زنده:** [مشاهده و تست ربات فروشگاه شیک‌پوش](https://shikpoosh-sales-agent.streamlit.app)

دستیار فروش خودمختار (Agentic) برای یک فروشگاه اینترنتی پوشاک، ساخته‌شده با **LangGraph**. این ایجنت به‌جای پاسخ‌های از پیش نوشته‌شده، با فراخوانی ابزار (Tool Calling) به دیتابیس واقعی فروشگاه متصل می‌شود، موجودی و قیمت را استعلام می‌گیرد، و در انتها سفارش مشتری را با اعتبارسنجی کامل در پایگاه‌داده ثبت می‌کند.

---

## ✨ قابلیت‌ها

| قابلیت | توضیح |
|---|---|
| 🔍 استعلام هوشمند انبار | جست‌وجوی کالا بر اساس نام، دسته‌بندی یا توضیحات — بدون هیچ اطلاعات ساختگی از سمت مدل |
| 📝 ثبت سفارش با اعتبارسنجی | بررسی فرمت شماره موبایل ایرانی، موجودی کالا و تکمیل بودن اطلاعات مشتری پیش از ثبت |
| 💾 پایداری داده | ذخیره‌سازی سفارش‌ها در SQLite با شماره پیگیری یکتا |
| 📊 پنل مدیریت زنده | نمایش لحظه‌ای موجودی انبار و سفارش‌های تازه در سایدبار |
| 🗣️ گفت‌وگوی فارسی طبیعی | شخصیت «شایان»: مودب، پرانرژی و کاملاً بومی‌سازی‌شده |

## 🧠 معماری

ایجنت با LangGraph به‌صورت یک گراف چرخه‌ای (Cycle) ساخته شده:

```
START → agent → (نیاز به ابزار؟) → tools → agent → ... → END
```

- **نود `agent`**: پیام سیستمی + تاریخچه مکالمه را به مدل Groq می‌دهد و تصمیم می‌گیرد پاسخ نهایی بدهد یا ابزاری صدا بزند.
- **نود `tools`**: دو ابزار `search_products` و `register_order` را اجرا می‌کند و نتیجه را به مکالمه برمی‌گرداند.
- این چرخه تا جایی ادامه دارد که مدل دیگر نیازی به فراخوانی ابزار نبیند.

## 🚀 راه‌اندازی

### پیش‌نیاز
- Python 3.10+
- یک کلید API رایگان از [Groq Console](https://console.groq.com)

### نصب

```bash
git clone https://github.com/<username>/shikpoosh-sales-agent.git
cd shikpoosh-sales-agent

python -m venv venv
source venv/bin/activate      # ویندوز: venv\Scripts\activate

pip install -r requirements.txt
```

### تنظیم متغیرهای محیطی

یک فایل `.env` در ریشه پروژه بساز:

```env
GROQ_API_KEY=your_groq_api_key_here
```

### اجرا

```bash
streamlit run app.py
```

برنامه روی `http://localhost:8501` بالا می‌آید.

## ⚠️ نکات مهم برای توسعه

- محصولات فعلاً در `data.py` به‌صورت درون‌حافظه‌ای (in-memory) تعریف شده‌اند؛ برای استفاده در پروداکشن بهتر است این بخش هم به دیتابیس منتقل شود، چون با هر ری‌استارت اپ، تغییرات موجودی ریست می‌شود.
- فایل `shop.db` و `.env` باید همیشه در `.gitignore` بمانند تا اطلاعات مشتری و کلید API لو نروند.
